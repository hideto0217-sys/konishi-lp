問題は「内製だから」ではなく、改善工程が途中で切れやすいこと

楽天商品ページを自社で改善できる店舗は多くあります。内製そのものが転換率低下の原因ではありません。

転換率が上がらないときは、原因特定 → 仮説 → 制作 → 実装 → 検証のどこが抜けているかを確認します。

1｜「見た目を良くする」を改善目的にしない

デザイン変更、画像追加、コピー修正が目的になると、何の購入判断を動かす変更か分からなくなります。先に商品別アクセス・CVRを見て、停止点を決めます。

2｜担当者の感覚だけで原因を決めない

「この画像が弱い」「説明が長い」といった仮説は出発点です。R-Karteなどで商品別のアクセス・転換率・離脱を確認し、どの数字を動かすのかを固定します。

3｜制作できることと、訴求を決められることを分ける

画像制作やHTML更新ができても、何を主役にするか、どの比較基準で選ばせるかは別の判断です。制作作業を増やす前に、商品名を消しても成立する主要価値を決めます。

4｜一度に複数箇所を変えすぎない

サムネイル、価格、商品説明、FAQ、レビュー表示を同時に変えると、CVRが動いても原因を学習できません。主要変更と検証指標を一つに絞ります。

5｜更新した時点で完了にしない

内製では制作・反映までが業務として完了しやすく、その後の検証が後回しになることがあります。変更日、対象商品、変更内容、比較期間、CVR・注文数を同じ単位で記録します。

6｜外注するなら「作業」ではなく不足工程を外へ出す

内製が悪いから外注するのではありません。原因分析はできるが制作が足りない、制作はできるが構成設計が弱い、検証まで回らないなど、不足している工程だけを外へ出します。

外注先を比較するときも、AIを使うか使わないかだけでは判断しません。確認するのは、誰が原因分析を行い、主要訴求と構成を決め、その判断に責任を持つかです。AIを使っていても、戦略・訴求・構成を人が設計し検証できるなら、単純な量産とは別です。逆に、判断主体が曖昧なまま制作量だけ増えるなら、不足工程は埋まりません。

内製で確認する工程：
原因特定 → 仮説 → 訴求・構成 → 制作 → 実装 → 検証。
人ではなく、抜けている工程を特定する。

自社改善で確認する6つの工程

  • 商品別データで停止点を決める
  • 原因仮説を作る
  • 主要訴求・構成を決める
  • 変更範囲を絞って制作する
  • 実装後にCVR・注文数を検証する
  • 不足工程だけ外注するか判断する

「自社でやるか、外注するか」より、改善工程が一周するかを見る

内製でも外注でも、転換率改善に必要なのは工程がつながることです。誰が作るかではなく、原因から検証までが切れずに回るかを判断基準にします。
